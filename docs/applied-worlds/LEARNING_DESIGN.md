# Applied learning design

The six available worlds live under Applications → Applied 3D Worlds. Discover, Explore, Challenges and My Learning remain; existing tools, Prediction Studio and the earlier builder remain intact. Sales is the first verified vertical slice, followed by Marketing, ML, the arm, Finance and GIS. Each was checked before proceeding to the next.

The shared journey has six accessible, skippable stages: Discover → Predict → Experiment → Understand & Prove → Mission → Build. One task card accompanies one main scene. Default controls are the two decision coordinates and, where useful, a learning rate or route selector. Model assumptions, extra parameters, matrix/glossary, comparison and code stay collapsed. Foundation/Deeper/Advanced preferences change disclosure, not permission to learn. All fundamental domain restrictions are visible regardless of level.

Every world has an analogy, symbol/unit glossary, two numerical examples that reset to their declared assumptions, a justified interactive derivation, counterexample/boundary case, three mission levels, seeded cases and a local remix/export. The existing DerivationStepper, WorkedExample, SceneFrame and lazy ThreeStage are extended. No decorative surface is labeled proof. Gradient/parameter geometry is distinguished from feature-space observations and physical workspace.

Mission assumptions are frozen; objective grading independently checks their values, input validity, constraints and chosen principle. A hint/reveal stays guided for the same scenario even when its seed repeats. A solution reveal requires an attempt. Free text is never automatically marked understood: reasoning is unreviewed until the learner marks a transparent self-check. Correctness describes that attempt only. History is bounded and disclosed by the code; no mastery percentages, points, streaks or account are added.

The ML world freezes parameters before displaying its fixed holdout. Freeze/guidance writes are durable before the UI reports completion; a reload race discovered in browser testing was repaired. The fixed set remains consumed during guided development. This is a teaching workflow, not secure proctoring. The existing full Prediction Studio is linked rather than rebuilt.

Build projects contain model version, finite parameters, original assumptions, prediction/reflection and dated evidence. JSON is strictly validated; CSV and a readable report accompany standalone standard-library Python. Import is a remix, not a new independent achievement. Marketing additionally offers a saved experiment worksheet for randomization, treatment/control/window, outcome and uncertainty/sample-size caveats. Existing project types and old backups retain their formats. Applied records are an additive optional section of learning schema v2; original raw v2 data is protected before the upgrade.

## Real novice and educator review — NOT RUN

The owner should recruit 3–5 beginner volunteers, not invented participants. Give each one world and a fresh browser profile. Observe without coaching: find the goal, make a prediction, change a numeric input, identify the matching geometric change and formula, explain one derivation step, solve a fresh case without hints, then save/export a project and state a limitation. Record the actual explanation, help used, confusion and transfer result. A later unfamiliar case provides qualitative revisit evidence, not a certified retention measure.

Ask an independent mathematics educator to check piecewise Sales derivatives, boundary optimization, coordinate-gradient scaling, Marketing fixed/at-most objectives and randomized estimands, ML feature/parameter spaces and holdout handling, robot radians/frames/path bound, Finance concavity/units, and GIS graph-versus-continuous optimality. Human screen-reader and physical phone touch/orbit/pinch sessions remain separate open checks. Small samples are design input, not statistical proof of effectiveness.
