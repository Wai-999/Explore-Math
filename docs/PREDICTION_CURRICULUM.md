# Prediction curriculum and implementation audit

## Completed candidate

Three interactive projects follow the same eight-stage process: frame → inspect data → choose evaluation → train → diagnose → freeze/test → decide → transfer/rebuild. Energy regression, machine-maintenance classification, and known-store weekly demand forecasting each have a typed prediction contract, original dataset generator, feature-availability questions, meaningful baseline, correct split, live training, validation diagnostics, a frozen final protocol, operational rubric, interpretation/decision journal, seeded numeric transfer, worked guidance, and runnable Python material.

The four explanation depths retain stable preference values: intuition, foundations, advanced (professional practice), research. Seven professional perspectives explain competing decisions. Navigation is progressive but permits inspection/skipping; opening content is not awarded mastery.

Browser kernels implement standardized linear/ridge and logistic gradients, stable log loss/sigmoid, a one-split tree baseline, MAE/RMSE/bias/R², confusion counts, precision/recall/specificity, Brier/log loss, stepped average precision, tied AUC, and reliability bins with counts. Model comparison uses development observations only. Final test controls lock preprocessing, coefficients, inputs, seed, threshold, model family, and shift settings, including after reload. Fresh seeded experiments archive completed journals; a new seed is not external real-world validation.

Python materials add median-imputation pipelines, forests/boosting, validation-only calibration, separate policy selection, grouped/temporal tuning, an energy nested-forward evaluation example, learning curves, seed sensitivity, rectangular SVD reconstruction/orthogonality, training-only PCA, and a licensed UCI historical-data transfer notebook. All notebooks are saved with executed outputs. Their worked results should be withheld when assigning independent exercises.

Storage schema v2 migrates existing v1 progress while retaining the original v1 browser key. Backups include fitted teaching sessions, decisions, archived journals, guidance flags, structured attempts, and misconception feedback. Corrupt or incompatible models are rejected; no remote storage is introduced.

## Prerequisite sequence

Coordinates and arithmetic → functions/residuals → averages and baseline errors → matrix/projection view of regression → derivatives/gradients → optimization and regularization → binary probability and log loss → decisions/thresholds/calibration → grouped/time evaluation → error diagnosis/uncertainty → conditional operating recommendation → SVD/PCA and deeper numerical reasoning.

Short hand calculations connect the browser to readable code. The notebooks provide full runnable implementations; the browser’s compact pseudocode is explicitly labeled conceptual. Prediction, explanation, and causal intervention remain distinct.

## Limits kept beside the experience

Original synthetic data does not establish real usefulness. Maintenance groups have four historical snapshots; alert capacity is an illustrative per-batch convention. Demand assumes no stockouts and has a synthetic 12-week season. Browser residual bands are empirical, not calibrated guarantees. Free-text reasoning is saved for human review. The larger mathematical roadmap remains visible in My Learning and the studio.
